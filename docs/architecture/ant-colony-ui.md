# 玄驹主面板：蚁巢剖面设计

> 2026-11-10 现状：巢室剖面（五室、蚂蚁个体、巢道）已从代码中移除，本文只作历史设计记录。
> 现行形态见 [Client 轨道罗盘页面设计](ant-client-design.md) 顶部说明：一张卡 + 上游活动面板结构。

状态：设计定稿（2026-11-07，用户裁定「主面板用蚁群风格」）。配套 `docs/architecture/ant-refactor-v2.md`。
适用范围：`client.js` 的 keyed 主面板与侧栏 slot。不改 Host 契约、不改动作面。

## 1. 一句话

主面板不是看板，是**一具蚁巢的剖面**：团队是一窝，成员是个体蚂蚁，任务是它们在蚁道上的搬运物，阶段是巢室。所有数字仍然是 WAL 折叠出来的事实，只是换了一种「看一眼就知道窝里有没有出事」的表达。

## 2. 隐喻与职责

| 界面实体 | 隐喻 | 承载事实 |
|---|---|---|
| 巢 | 团队 | `teamId`、lifecycle、目标 |
| 蚁后室（中央） | 蚁后 | 协调者的当前状态与它最近的动作 |
| 巢室 ×4 | 任务阶段 | 待派 / 待放行 / 执行中 / 已完成 / 异常（五个室，含孵化室） |
| 蚁道 | 任务依赖边 | 依赖关系与近期通过量（信息素浓度） |
| 蚂蚁 | 成员 | 成员状态、所在阶段、当前 attempt |
| 背负物 | 任务 | 蚂蚁身上的一块矩形 = 正在搬的任务 |
| 信息素粒子 | 邮箱消息 | 消息流动方向（不显示内容） |
| 巢门 | L2 放行闸门 | 待放行任务数与放行动作 |

## 3. 巢室布局（五室）

左→右沿一条主蚁道排列，蚁后室居中偏下：

| 室 | 阶段 | 进入条件 | 出室条件 |
|---|---|---|---|
| 孵化室 | 待派 | 任务已确认、依赖未满足或未放行 | 依赖满足且被放行 |
| 闸门厅 | 待放行 | 依赖满足、门已通过、处于待放行批 | 用户 `batch.release` |
| 主通道 | 执行中 | 已有 open attempt | attempt 终态 |
| 储藏室 | 已完成 | 自证 + 他证双 pass | 归档 |
| 废料堆 | 异常 / 需干预 | 门不通过超 2 轮、候选全废、`run.interrupted` | 人工接管或重派 |

废料堆不隐藏历史：堆内分「当前卡住」与「历史异常」两组，后者折叠。

## 4. 布局与尺寸

三栏沿用现有 `ant-body` 网格：

```
┌──────────────┬────────────────────────────┬──────────────┐
│ 巢室索引 220px│ 巢穴剖面 SVG（弹性）        │ 检查台 320px │
│ 五室 + 计数   │ 室为实心块，蚁道为贝塞尔    │ 选中项事实    │
│ 待放行 badge  │ 蚂蚁在其中移动              │              │
├──────────────┴────────────────────────────┴──────────────┤
│ 活动流（默认折叠）：进行中 3 · 空闲 2 · 需干预 1            │
└──────────────────────────────────────────────────────────┘
```

- SVG `viewBox="0 0 320 200"`，等比缩放，不随窗口拉伸变形。
- 断点与现有 CSS 一致：1024 收起检查台为抽屉；768 只留剖面 + 顶部计数；420 单栏。
- 成员 >8 时室内按 4×2 网格排列，超出显示 `+N`，点开在检查台列出。

## 5. 交互

| 动作 | 结果 |
|---|---|
| 点巢室 | 剖面聚焦该室（其余 0.25 透明），检查台列出室内容 |
| 点蚂蚁 | 检查台显示成员：模型、当前工具、目标文件、步数、耗时、足迹 |
| 悬停蚁道 | 显示依赖两端与信息素值（近 10 分钟通过数） |
| 点巢门 | 展开待放行批清单：任务、负责成员、预计 token |
| `Enter`（闸门聚焦时） | 放行当前批 = `batch.release` |
| `1`–`5` | 切换巢室 |
| `Esc` | 回到全巢视图 |
| 右键成员 | 暂停 / 接管 / 终止（人工动作，不进模型侧） |

放行必须可在键盘完成：L2 的瓶颈是「要有人按下放行」，不让它依赖鼠标。

## 6. 视觉规范

- **单色**：沿用 `--dsw-alias-*` 变量；巢体为实心剪影，巢室靠负空间切出（符合你偏好的「实心形体 + 负空间出细节、不描边、不渐变」）。
- 蚂蚁：3 段实心剪影（头/胸/腹），长约 6px，无描边；静止与移动只差位置，不闪烁。
- 唯一的强调色只用于两处：`待放行` 计数与 `需干预`。
- 文字最小 11px；室名常显，任务标题只在悬停或聚焦时出现（剖面不塞满文字）。
- 动效：蚂蚁沿蚁道 2–4s 匀速搬迁；卡住时停在室口抖动两次后静止；减少动效偏好（`prefers-reduced-motion`）下全部改为静态定位。

## 7. 数据映射（UI ← 折叠视图）

| UI 元素 | 来源字段 |
|---|---|
| 室计数 | `view.tasks` 按 stage 分组计数 |
| 待放行 badge（侧栏） | `batch.pending` 长度，与闸门厅同一来源 |
| 蚂蚁位置 | `view.members[].status` + 该成员 open attempt 的任务 stage |
| 背负物 | open attempt 的 `taskId` |
| 蚁道 | `view.tasks[].dependsOn` |
| 信息素值 | 近 10 分钟 `mail.sent`/`attempt.dispatched` 计数（只做视觉量） |
| 废料堆条目 | `needs_attention` 任务 + `run.interrupted` 记录 |
| 成本角标 | `spend` 按成员聚合，悬停显示明细 |

面板只读 `team/get` 视图，不直接读 WAL 文件；无团队时显示空巢轮廓 + 一句「还没有蚁群」。

## 8. 设置页（C 方案：页面写 JSON）

插件自带设置页，写入与 profile 同一份 JSON（`$DSH_HOME/ant.json`）：

| 字段 | 默认 | 说明 |
|---|---|---|
| `autonomy` | `L2` | L1 逐任务 / L2 批量放行 / L3 全自动（切 L3 二次确认） |
| `batchWindowMinutes` | `30` | 批次窗口 |
| `maxActiveAttempts` | `8` | 并发上限（4–8 人规模） |
| `defaultVariants` | `1` | 采样默认候选数，上限 3 |
| `variantWriteTasks` | `false` | 写类任务是否允许 N>1（默认禁止） |

设置页改动即时生效（读配置在每次动作前），不要求重启。

## 9. 与现有实现的迁移

| 现在 | 之后 |
|---|---|
| `Orbit`（轨道罗盘 SVG） | `Nest`：巢室 + 蚁道 + 蚂蚁 |
| `Inspector`（任务检查台） | 保留，改名 `InspectionDesk`，增加成员页与批次页 |
| `MainPanel` 三栏网格 | 保留网格，只换中栏内容 |
| 侧栏 `Sidebar` | 保留，增量：待放行计数徽标 |
| `locale` 的 `compass: '轨道罗盘'` | `nest: '蚁巢'`，新增五室名与「待放行」词条 |

不改 `PANEL_ID`（`ant`）、不改 slot 注册方式、不改 Remote 调用。

## 10. 验收

1. 1440 / 1024 / 768 三档下剖面不变形，五室可见，文字不重叠。
2. 五室计数与 `team/get` 视图一致；侧栏 badge 与巢门数字一致。
3. 全键盘可完成：切室（1–5）→ 聚焦巢门 → `Enter` 放行。
4. 去掉强调色后仍能区分五室（靠形状与标签），验证不依赖颜色。
5. `prefers-reduced-motion` 下无动画，信息不丢失。
6. 无团队 / 数据未就绪 / 成员 >8 三种边界各有明确呈现。
